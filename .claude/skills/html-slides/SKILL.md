# 슬라이드 스킬 1 — HTML 덱 짓기·고치기

PPT 대신 **HTML 파일 하나**로 만드는 발표 덱. 브라우저에서 열고 ← → 로 넘김. 인터넷 주소로 올리면 청중도 자기 노트북·휴대폰에서 같이 봄.

## 견본

| 파일 | 쓰임 |
|---|---|
| `templates/basic-deck.html` (이 스킬 폴더 안) | 교육·강의·보고 덱 출발점 · 베이지 바탕 · 자주 강조 · 명조 제목 |

새 덱은 **견본 복사**로 시작. 바꾸는 자리 셋 — ①`:root` 색 ②`<section class="slide">` 본문 ③맨 아래 `store` 열쇠 이름(`my-deck.zoom` → 덱마다 다르게). 넘김·차례·글자 크기 코드는 손대지 않음.

## 얼개

- 한 장 = 한 화면 `<section class="slide" id="s-…" data-title="…">` · 높이 100vh · 세로 스크롤 스냅
- 넘김: ←→ ↑↓ · 스페이스 · PageUp/Down · Home/End · 오른쪽 위 ‹ › 단추 · 쪽 번호 「n / 전체」
- 「차례」 단추 — `data-title` 로 자동 생성. **`data-title` 도 이름표**로
- 「글자 ＋/−」 — `--zoom` 0.7~1.6, `localStorage` 에 덱마다 다른 열쇠로 기억. 읽기·쓰기는 try/catch
- 「띠 숨기기」(H 키) — 투사할 때 위 띠·단추를 감춤
- 글자 크기 기준 `html{font-size:calc(clamp(12px, min(1.12vw, 1.98vh), 24px) * var(--zoom))}` — 화면이 달라도 비율 유지
- 인쇄(@media print) 한 장 한 쪽 · 900px 아래는 휴대폰 배치
- `<meta name="robots" content="noindex,nofollow">` — 검색에 안 걸리게
- 글꼴 Noto Sans KR / Noto Serif KR(구글 폰트)
- 장 번호 = 쪽 번호(표지 1번). 발표자가 「몇 번 장」이라 말할 때 화면 번호와 맞음

## 장 종류 (견본에 다 들어 있음)

| class | 쓰는 곳 |
|---|---|
| `cover` | 표지 |
| `divider` | 파트 간지 |
| `quiz` + `.reveal` | O X 퀴즈 · 「정답 보기」 단추 |
| `.quad` | 개념 네 칸 |
| `.warn` | 유의사항 셋 |
| `motto` | 사자성어·표어 한 장 |
| `.prompt` + 「복사」 단추 | 청중이 ChatGPT 에 붙여넣을 프롬프트 |
| `qa` | 마침 · 감사 |
| `concept` | 부록 개념 상세 |
| `tight` | 글이 많은 실습 안내 |

설교·사진 이야기 덱이면 덧붙일 장: `ask`(질문 한 줄) · `word`(말씀 명조 인용) · `full`(사진 한 장 꽉 차게 + 한 줄)

## 순서

1. **재료 확인** — 구성안·원고·사진·영상. 구성안이 없으면 장 목록(번호·`data-title`·한 줄 내용)을 먼저 보여 주고 확인받음
2. **견본 복사** — `<덱이름>.html` · 사진은 `<덱이름>/` 폴더. 머리 주석에 덱 이름·날짜·요청 내용을 적음
3. **장 짓기** — 한 장에 메시지 하나(아래 규칙)
4. **사진·영상 넣기** — 아래 「사진·영상」
5. **검사** — 아래 「올리기 전 검사」
6. **올리기** — 정적 호스팅(Vercel · GitHub Pages · Netlify 등)에 HTML 과 그림 폴더를 같이. 올린 뒤 페이지와 **파일마다** 열리는지 확인

## 문체 규칙

- **제목은 이름표.** 「교육 목표」「실습 1. 접속과 로그인」「유의사항」「소결론 1」
  - 쓰지 않는 꼴: 「검색은 찾고, 생성은 만든다」「오늘 갈 길」(서술·대구·비유) · 「무엇을 어떻게 했는가」(물음)
  - 예외: 사용자가 직접 준 문장(설교 제목·질문 문구·퀴즈 문항)은 **그대로** 씀
- **본문은 개조식 명사형.** 구어·비유 문장 금지
- **줄표(—)·화살표(→) 0개.** 가운뎃점(·)으로
- **지어낸 용어 금지.** 표준 용어(프롬프트·로그인·입력창·파일 첨부·업로드)
- **단추 이름은 실제 화면 그대로**
- **자랑 금지** — 숫자로 발표자 업적을 내세우지 않음

## 한 장 한 메시지

- 사진·키워드·질문·인용 **중 하나만 크게**
- 사진 장에는 큰 글 대신 짧은 이름표 한 줄(장소 · 날짜). 화면 캡처는 출처만
- 사진을 배경으로 깔면 글 칸은 반투명 흰 칸 또는 짙은 칸으로 읽히게
- 겹치는 장은 뺌 · 결론 셋은 3분할 한 장으로 모음

## 사진·영상

- 자리 먼저: 파일이 없으면 회색 자리에 **넣을 파일 이름**이 보이게(`img` error → `.none`). 덱은 사진 없이도 굴러감
- 사진 폴더에 `README.md` — 파일 이름 ↔ 장 표 · 출처
- 사진 기준: 가로(16:9 가까이) · **2MB 이하**. 휴대폰 상태 띠·남의 계정 이름·로고는 잘라 냄
- 주인공이 가운데 오게 자름. 작은 사진을 크게 늘려 깨지면 원래 크기 가까이 두고 뒤에 같은 사진을 흐리게
- 영상: HEVC 는 H.264 로(`ffmpeg -c:v libx264 -crf 23 -movflags +faststart`). 포스터 jpg 따로. 장이 화면 절반 이상 들어오면 재생·벗어나면 멈춤
- ★얼굴·개인 사진은 공개 주소 = 누구나 봄. 넣기 전 확인

## 올리기 전 검사

```
node <이 스킬 폴더>/scripts/style_check.js <덱>.html     # 제목·본문 문체
grep -c '—\|→' <덱>.html                                 # 줄표·화살표 (장 본문 기준 0)
node <slides2 폴더>/scripts/check_deck.js <덱>.html       # 넘침·깨진 그림 (원고 검사 1건 걸림은 스킬 1 덱에선 정상)
```

- **1920×1080 · 1366×768** 두 크기에서 모든 장 넘침 0. 사진 장은 스크린숏으로 눈으로 확인
- 단계 목록 `li` 가 grid 면 둘째 줄 span 에 `grid-column:2`
- 깨진 그림 0 · 「차례」 장 수 = 실제 장 수
- 검사기는 Node.js 와 Playwright 가 필요: `npm i -D playwright && npx playwright install chromium`

## 고치기 지시 받을 때

- 사용자는 **화면의 장 번호**로 말함(「12번 장」「8·9번 순서 바꿈」). 표지가 1번. 차례 목록에서 번호·`data-title` 로 찾음
- 한 지시 = 한 커밋(장 번호를 메시지 앞에) — 되돌리기 쉬움
- 장을 넣거나 빼면 뒤 번호가 밀림 → 다음 지시를 받을 때 지금 번호로 다시 셈

> 핵심 칸 · 발표자 원고 · 원고 창이 필요한 학술 발표·강연은 **슬라이드 스킬 2**(`slides2`)로.
