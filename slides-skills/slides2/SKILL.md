# 슬라이드 스킬 2 — 핵심 칸 · 발표자 원고 · 원고 창

> 스킬 1(`html-slides`)의 얼개·문체 규칙은 그대로 지킨다. 이 문서는 **그 위에 더한 것**만 담는다.

## 견본

| 파일 (이 스킬 폴더 안) | 쓰임 |
|---|---|
| `templates/poster-deck.html` · `templates/sample.svg` | 학술 발표 덱 출발점 · 먹색·상아·주홍 포스터 테마 · 7장 · 3분 배정 |
| `scripts/check_deck.js` | 넘침 · 깨진 그림 · 원고 짝 · 핵심 칸 · 배정 합계 · 원고 창 연동 한 번에 |

새 덱은 견본을 복사해 시작. 바꾸는 자리 — ①`:root` 색·글꼴 ②`<section class="slide">` 본문 ③`presenterData` JSON ④맨 아래 `store` 열쇠(`my-talk.zoom`)와 `BroadcastChannel` 이름(`my-talk-deck`)을 덱마다 다르게. 넘김·차례·글자 크기·띠 숨기기·핵심 칸·원고 칸·원고 창 코드는 손대지 않는다.

## 스킬 1과 다른 점

| | 스킬 1 | 스킬 2 |
|---|---|---|
| 오른쪽 | 없음 | 장마다 **「핵심」 칸**(표지 제외) · 청중도 봄 |
| 원고 | 없음 | **발표자 원고** · 배정 초 · 다음 장 연결 멘트 |
| 원고 보는 길 | | ①P 키 칸(연습용 · 투사 화면에도 보임) ②**「원고 창」** 노트북용 별도 창 `?notes=1` · 덱 창과 같이 넘어감 · 경과 시계 |
| 테마 | 견본 그대로 | **행사 포스터·받은 이미지에서 색·글꼴을 뽑음** |
| 검사 | 손으로 | `scripts/check_deck.js` 한 줄 |

## 순서

1. **재료 받기** — 디자인 테마(포스터 이미지) · 원고(논문 전문 .docx 등) · 발표자의 스토리 구성안 · 발표 시간. 빠진 것이 있으면 먼저 달라고 한다. **구성안 없이 덱을 짓지 않는다.**
   - .docx 는 `unzip` 후 `word/document.xml` 에서 문단을 뽑는다. 그림은 `word/media/`.
2. **장 구성안 제안** — 표 하나: 번호 · 장 제목(이름표) · 내용 · 논문 장절 · 배정 시간. 함께 낸다:
   - **누락 대조**: 논문 초록의 쟁점마다 몇 번 장에서 다루는지. 구성안에 없는 논문 핵심(새 판독·비교표·결론 문장)은 끼워 넣고 «끼워 넣었다»고 밝힌다.
   - **사용자가 정할 것**만 번호로(구성안에만 있고 논문에 없는 내용 · 확인 안 된 사실 · 포스터와 말이 다른 발표 시간). 권하는 안을 붙인다.
   - 「가자」 하기 전에는 짓지 않는다.
3. **테마 이식** — 포스터에서 바탕·글자·강조색 셋과 제목 글꼴을 뽑아 `:root` 토큰으로. 견본 예: 먹색 `#15120f` · 상아 `#f1ebdf` · 주홍 `#e9533b` · 제목 Black Han Sans · 본문 Noto Sans KR · 한문 Noto Serif KR · 행사 도장을 표지·간지에.
   - 제목 글꼴에 없는 글자 확인: Black Han Sans 는 로마 숫자 「Ⅱ·Ⅲ」이 깨짐 → `II` `III` 로.
   - 포스터 글꼴은 이미지만으로 확인 불가 · «비슷한 글꼴»이라고 말한다.
4. **장 짓기** — 스킬 1 규칙 그대로(제목 이름표 · 본문 개조식 · 줄표·화살표 0). 학술 덱 추가:
   - 한문 인용은 `.han` 칸(원문 · 독음 · 국역 · 출처).
   - 그림 장은 논문 그림 번호와 출처를 캡션에.
   - 이야기 줄기(「사건 수사」 꼴)는 **간지·장 머리 띠**로만 · 장 제목은 여전히 이름표(「장면 1. ○○의 의문」「증거 1. ○○ 도상」).
   - 끝에 참고자료 장(그림 출처 · 선행연구 · 원전) · 번호 A B C · 원고는 «질의응답 참고»·배정 0초.
5. **핵심 · 원고 쓰기** — `presenterData` 에 장마다 `{"id","seconds","key","script","transition"}`.
   - `key`: 오른쪽 칸 한 줄 · **명사형 · 물음 꼴 금지** · 40자 안팎.
   - `script`: 소리 내어 읽을 원고 · 「…입니다」 꼴 · 초당 4음절 안팎(30초 ≈ 120음절).
   - `seconds` 합계 = 발표 시간 정확히(15분 = 900). 간지 5초 · 핵심 장 45~50초.
   - 문체 검사가 원고의 서술형 종결을 잡는 것은 정상(원고는 말글). **`key` 와 장 본문만 깨끗하면 됨.**
6. **검사**
   ```
   node <html-slides 폴더>/scripts/style_check.js <덱>.html             # 「물음」·장 본문 걸림만 확인 (원고 서술형은 무시)
   node <이 스킬 폴더>/scripts/check_deck.js <덱>.html --total 900 --sync --shots <스크린숏 폴더>
   ```
   넘침 0 · 깨진 그림 0 · 원고 짝 · 핵심 칸 · 배정 합계 · 원고 창 연동까지 한 번에. 스크린숏은 눈으로 본다(표지 도장과 글자 겹침, 간지 숫자 깨짐).
   - 검사기는 Node.js 와 Playwright 가 필요: `npm i -D playwright && npx playwright install chromium`
7. **올리기** — 스킬 1과 같음(정적 호스팅 · 파일마다 열리는지 확인).
8. **사용자에게 드릴 것** — 주소 + 원고 창 쓰는 법(아래).

## 원고 창 쓰는 법 (발표자에게 드리는 글 · 그대로 씀)

1. 발표장 노트북(윈도우) 키보드 · `윈도우 키 + P` → **「확장」** (「복제」면 원고가 프로젝터에 보임)
2. 노트북 크롬/엣지 주소창 · 덱 주소 열기
3. 덱 오른쪽 아래 **「원고 창」** 단추 → 새 창. 팝업 차단이면 주소창 오른쪽 표시에서 허용
4. 덱 창은 프로젝터 화면으로 끌어 **F11** · 원고 창은 노트북 화면에
5. 어느 창에서 ← → 를 눌러도 두 창이 같이 넘어감 · 원고 창 「시계 시작」
- 두 창은 **같은 브라우저 · 같은 주소**여야 같이 움직인다(BroadcastChannel). 발표장 장비로 미리 시험할 것.

## 함정 (실제로 겪은 것)

- **발표자 이름**: 학술 발표에 쓰는 이름(본명·필명)을 먼저 확인.
- **장 번호 = 쪽 번호**: `.s-head .n` 을 `i + 1` 로. 표지 0부터 세면 「몇 번 장」과 어긋남.
- 표지의 `inline-block` 꼬리표가 flex 세로 줄에서 가로로 늘어남 → `align-self:flex-start`.
- 포스터 꼬리표·도장을 표지 오른쪽에 두면 다른 글자를 가림 → 스크린숏으로 확인.
- 생몰년처럼 자료마다 다른 값은 덱에 넣지 않거나 사용자에게 묻는다.
